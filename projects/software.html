Project 1

Spendable — KB AI 공모전 "미래준비" 탭 프로토타입

"지금 이거 사도 될까?"에 미래의 생활비로 답해 주는 KB스타뱅킹 프로토타입입니다. 은퇴 계산은 입력값(현재 나이, 월 소득, 저축률, 희망 은퇴 나이)이 하나라도 없으면 계산 자체가 의미 없는데, 그렇다고 막으면 사용자가 이탈합니다. 계산 함수가 부족한 값을 임의로 추정해 채우지 않고 missing_data / invalid_age / ready 상태를 명시적으로 반환하고 화면은 상태만 보고 분기하도록 설계했습니다. 금융 계산에서 사용자가 안 넣은 값을 임의로 채워 그럴듯한 숫자를 보여주는 건 나중에 신뢰를 깨뜨리는 선택이라고 봤기 때문입니다.

구매 판단(judgeStatus)은 "위험해요"로 끝내지 않고 대안 3개(다음 달 구매/할부/예산 낮추기)를 항상 함께 계산합니다. 마이데이터·LLM 교체 지점은 financeDataAdapter, mockChatAdapter 두 어댑터로 격리했고, 폴더 규칙(core=순수 계산·React import 금지, state=Zustand, components=UI)을 CLAUDE.md에 박아 두었습니다. zustand persist의 얕은 병합 때문에 lifePlan 하위 필드가 undefined가 되어 화면이 죽는 버그는 커스텀 깊은 merge로 고쳤습니다. core 순수 함수는 Vitest 유닛 테스트 13개로 회귀를 잡습니다.

Project 2

badok — Unity 3D 오목 AI (넥토리얼 지원용)

15×15 보드에서 완전탐색 미니맥스는 실시간이 불가능해, 이미 둔 돌 주변 N칸만 후보로 삼는 가지치기와 알파베타 프루닝으로 계산량을 줄였습니다. 평가 함수는 열린4=100000, 막힌4=10000, 열린3=5000 같은 정석 패턴 점수입니다. AI 계산은 Task.Run으로 백그라운드 스레드에서 돌리고 Unity SynchronizationContext로 결과만 메인 스레드로 복귀시켜 화면이 멈추지 않게 했습니다.

Core(순수 C#, UnityEngine 미의존)와 Game(MonoBehaviour)을 분리해 둔 덕분에, 프로젝트 도중 2D UI 방식에서 3D 씬 방식으로 렌더링을 전면 교체할 때 Board.cs와 GomokuAI.cs는 한 줄도 수정하지 않았습니다. 보드 큐브를 localScale (16, 0.1, 16)으로 키운 뒤 돌을 그 자식으로 만들어 거대하고 납작한 원반이 그려지던 부모 스케일 상속 버그 등 3건을 재현·검증해 DEVLOG에 남겼습니다.

Project 3

산불 CCTV 협업 감지 — 비전문 도메인을 MSA로 분해

다중 CCTV 영상에서 연기·화재를 실시간 감지하고 발화 지점을 삼각측량하는 시스템입니다. ingest → detection → smoke-flow → fusion → alert 5개 마이크로서비스로 역할을 나누고 모두 Docker로 운영했습니다. YOLOv8 연기·화재 검출 + Farneback 광류 분석 + 다중 카메라 삼각측량으로 발화점을 추정하고, React + TypeScript 지도 대시보드에 표시합니다. 비전문 도메인을 구조로 분해해 MVP까지 완성한 사례입니다.
